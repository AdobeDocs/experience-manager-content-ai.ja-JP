# AEM コンテンツ AI 検索の基本を学ぶ

従来のサイト検索では、訪問者が入力した単語とコンテンツ内の単語を一致させます。 訪問者がコンテンツと同じ用語を使用している場合はうまく機能しますが、 質問したり、意図を表明したり、異なる表現を使用したりすると、失敗します。 検索は、サイト上での訪問者の意図を最も明確に示すシグナルの 1 つです。そのため、一致が見つからないと、多くの場合、ジャーニーの失敗（コンテンツが見つからない、エンゲージメントの低下、コンバージョンの損失）につながります。 訪問者は、入力した内容だけでなく、その意味を検索機能が理解することを期待するようになっています。 同じ意図を認識した基盤こそが、生成的な回答を実現します。

AEM コンテンツ AI 検索は、サイトの検索エクスペリエンスを置き換えるものではありません。キーワードの一致から、意味や意図の理解、質問への直接的な回答まで、検索エクスペリエンスを進化させるものです。 セマンティック検索では、既存の検索エクスペリエンスに意図を認識する検索機能が追加され、クエリがコンテンツの正確な文言を共有しない場合でも、関連性の高いコンテンツが表示されます。 生成検索では、同じ検索基盤の上に構築され、サイト独自のコンテンツに基づいて、コンテキストに即した回答が生成されます。これは、セマンティック検索とは異なるステップです。

訪問者にとって、これは、より関連性の高い検索結果、自然言語サポート、検索結果がゼロになる件数の減少、より迅速な回答が得られることを意味します。 お客様のビジネスにとって、これは検索エクスペリエンスをゼロから再構築することなく、より優れた意図の一致、より強力なコンテンツの発見、AI 対応の検索基盤を実現することを意味します。 お客様のチームにとっては、これは、段階的なアップグレードとなります。既存の検索コンポーネントの機能を、新しい実装を必要とするのではなく、語彙検索からセマンティック検索、生成検索へと段階的に移行できます。

それを実現するには、コンテンツをどのようにコンテンツ AIに取り込むか、どのコンポーネントを使用して訪問者にそのコンテンツを提供するか、という 2 つのことを決める必要があります。 訪問者に適切な結果とインテントベースの回答を提供するには、コンテンツを接続し、検索コンポーネントをページに追加します。

## 前提条件 {#prerequisites}

開始する前に、次の条件を満たしていることを確認してください。

* 1 つ以上の AEM as a Cloud Service 環境を持つアクティブな Cloud Manager プログラムがある。
* ユーザーには、**オーサー**&#x200B;層と&#x200B;**パブリッシュ**&#x200B;層の両方で、**[!UICONTROL AEM ユーザー]**&#x200B;製品プロファイル（コンテンツソースの表示用）と **[!UICONTROL AEM 管理者]**（コンテンツソースの作成と編集用）が割り当てられています。 手順について詳しくは、[AEM 製品プロファイルへのユーザーの割り当て](contentsources.md#assign-product-profile)を参照してください。
* 環境の製品プロファイルが **Adobe Admin Console** でプロビジョニングされている。

>[!NOTE]
>
>Cloud Manager へのアクセス権のみでは不十分です。 また、コンテンツソースを表示または管理するには、オーサー層とパブリッシュ層の両方で AEM 製品プロファイルがユーザーに割り当てられている必要もあります。

## 手順 1a - 既存のインデックスを接続 {#option-a}

既存のリポジトリインデックスは、コンテンツソースのリストにソースタイプ AEM として自動的に表示されます（ページ、アセット、コンテンツフラグメントなど、インデックスの対象となる要素に基づいて表示されます）。 これらは&#x200B;**制限付き**&#x200B;でロックされた状態で開始され、コンテンツ AI を通じてまだ検索できません。

1. [Cloud Manager](https://my.cloudmanager.adobe.com/) にログインし、プログラムを選択して、設定する環境の「**[!UICONTROL コンテンツ AI 設定]**」タブを開きます。
1. 検索対象とするソース（例：**ページ**）を検索し、そのロックアイコンを選択します。 これを実行できるのは、**[!UICONTROL AEM 管理者]**&#x200B;製品プロファイルを持つユーザーのみです。**[!UICONTROL AEM ユーザー]**&#x200B;はコンテンツソースを表示できますが、検索性は変更できません。
1. **ソースを検索可能にしますか？**&#x200B;ダイアログをよく読みます 。 このインデックスが検索可能になると、Apache Oak のアクセス制御リスト（ACL）が適用されなくなるという警告が表示されます。 認証済みのユーザーが、そのコンテンツのすべてを取得できるようになります。 「**アクセス制御（ACL）は適用されず、このソース内のすべてのコンテンツが検索可能になることを理解しています**」をオンにして、「**検索可能にする**」を選択します。
1. ステータスが&#x200B;**使用可能**&#x200B;に変更されたことを確認します。 ソースに対して ACL がバイパスされていることを示す永続的なリマインダーとして、そのソースの横に警告アイコンが引き続き表示されます。
1. 結果を検証するには、テスト検索を実行します。

>[!WARNING]
>
>この方法で既存のインデックスを検索可能にすると、そのソースに対する Apache Oak の ACL が完全にバイパスされます。つまり、通常のリポジトリ権限に関係なく、認証済みのユーザーが検索を通じてそのコンテンツのすべてを取得できます。 完全に公開しても問題ないソースに対してのみ、これを実行してください。

>[!NOTE]
>
>ページコンテンツなど、サイトのコンテンツを含むインデックスが既にある場合に、このパスを使用します。 別のクロールメカニズムを設定する代わりに、このインデックスを使用してください。

## 手順 1b - Web サイトをクロール {#option-b}

サイトの検索インデックスがまだ存在しない場合は、このパスを使用します。 コンテンツ AI 独自のクローラーがインデックスを作成および更新します。 このクロール処理は、Cloud Manager およびこのガイドを通じて&#x200B;**獲得**&#x200B;とも呼ばれます。

1. 手順 1a と同様に、「**[!UICONTROL コンテンツ AI 設定]**」タブを開きます。
1. 「**[!UICONTROL ソースを作成]**」を選択し、フィールドに入力します。 新しいコンテンツソースを追加できるのは、**[!UICONTROL AEM 管理者]**&#x200B;製品プロファイルを持つユーザーのみです。

   | フィールド | 説明 |
   | --- | --- |
   | **[!UICONTROL コンテンツ AI 設定名]** | このソースの一意の ID。 作成後は変更できません。 |
   | **[!UICONTROL Web サイトアドレス]** | クロールするルート URL（例：`https://www.example.com/`）。 |
   | **[!UICONTROL URL を除外]** | *（オプション）*&#x200B;クロール中にスキップする URL パターン。 |
   | **[!UICONTROL 更新頻度]** | 週単位、日単位、日単位 4 回、60 分または 15 分。 |

1. 「**[!UICONTROL ソースを作成]**」を選択します。 獲得が自動的に開始され、ソースは&#x200B;**インデックス作成**&#x200B;に移行します。
1. **使用可能**&#x200B;に達するまでステータスを監視します。

   | ステータス | 意味 |
   | --- | --- |
   | **新規** | ソースが作成されたばかりです。自動獲得はまだ開始されていません。 |
   | **インデックス作成** | クロールとインデックス作成は処理中です。 |
   | **使用可能** | インデックス作成が完了しました - 検索クエリを提供する準備が整いました。 |

1. コンテンツが正しくインデックス作成されたことを確認するには、ソースの横にある「**検索**」アイコンを選択し、テストクエリを実行します。

>[!CAUTION]
>
>ソースが&#x200B;**[!UICONTROL インデックス作成]**&#x200B;のまま変わらない場合は、最初に（…）メニューから獲得を再試行してください。 それでも進まない場合は、web サイトのアドレスが一般にアクセス可能で、**[!UICONTROL URL を除外]**&#x200B;パターンですべてのページが除外されていないことを確認してください。

## 手順 2 - 検索コンポーネントを選択 {#choose-component}

ページ上で検索を実行できるコンポーネントは 2 つあり、それぞれ異なる基盤に基づいて構築されています。

| | セマンティック検索によるクイック検索（v3） | AEM コンテンツ AI 検索 |
| --- | --- | --- |
| 基盤 | 既存のクイック検索コアコンポーネント、v3 にアップグレード | 新しいスタンドアロンコンポーネント - Content AI API を直接呼び出します |
| コンテンツのソース | 既にインデックス内にある既存のサイトコンテンツ、セマンティック一致用に強化 | コンテンツ AI ソース（手順 1a または 1b） |
| 生成回答 | いいえ - 既存の結果リストの一致品質を向上させるのみ | はい - ソースと免責事項を含む、オプションの AI 生成の要約 |
| 最適なフィット | クイック検索を既に使用しているサイトで、より軽量で段階的なアップグレードが必要 | コンテンツ AI のすべての機能（セマンティック検索、生成検索、自然言語検索（NLS））に対する推奨コンポーネント |

## セマンティック検索によるクイック検索（v3） {#quicksearch}

サイトで既にクラシック [!DNL AEM] クイック検索コンポーネントを使用している場合、v3 では訪問者が切り替えられるオプトインの **AI 検索**&#x200B;切替スイッチが追加されます。新しいコンポーネント、プロキシ、コンテンツソースは必要ありません。

* 検索は引き続き現在と同様の JCR／QueryBuilder パスを通じて実行されます。結果用サーブレットや結果のレンダリング方法に変更はありません。
* 訪問者が切替スイッチを有効にすると、コンポーネントはクエリの先頭にプレーンキーワードのフルテキスト検索の代わりにセマンティック一致にルーティングする特別なマーカーを付加します。
* このパスには、生成回答の要約はありません。 これは、既存の検索結果リストの一致品質を向上させるものであり、生成 AI による回答を追加するものではありません。
* **手順 1（コンテンツ AI オンボーディング）は、このパスに適用されません。** 作成または接続するコンテンツソースがありません。このコンポーネントは、既存のページインデックスに対してクエリを直接実行します。

>[!NOTE]
>
>切替スイッチを有効にした後、セマンティック検索が期待どおりに機能しない場合は、サポートチケットを発行してください。

新しいコンポーネントやコンテンツソースを採用せずに、セマンティック検索を段階的にアップグレードする場合に、このパスを使用します。 生成回答エクスペリエンスが必要な場合、これは適切なパスではありません。その場合は AEM コンテンツ AI 検索を使用します。

## AEM コンテンツ AI 検索 {#gensearch}

AEM コンテンツ AI 検索は、セマンティック検索機能と生成検索機能の両方を使用して、訪問者がページからコンテンツソースを直接検索できるようにする [!DNL AEM] コアコンポーネントです。

>[!VIDEO](https://video.tv.adobe.com/v/3497308)

>[!NOTE]
>
>生成検索機能は、AI SKU 経由で別途購入してください。 お使いのアカウントでこの機能を有効にするには、アドビセールス担当者にお問い合わせください。

### 前提条件 {#gensearch-prerequisites}

* プロジェクトに [!DNL AEM] コアコンポーネントがインストールされていること。
* 1 つ以上のコンテンツソースが既に作成され、ステータスが&#x200B;**使用可能**&#x200B;であること。
* オーサーとパブリッシュの両方で、有効な API 資格情報とデフォルトのコンテンツソースを指定した **AEM コンテンツ AI クライアント** OSGi 設定（`ContentAIClientImpl`）が指定されていること。

コンポーネントをオーサーが使用できるようにする、クライアントライブラリを接続する、ダイアログを設定するなど、完全な設定ガイドについて詳しくは、[コアコンポーネントドキュメント](https://www.adobe.com/go/aem_cmp_library_jp)を参照してください。
